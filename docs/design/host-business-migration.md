# Go Host 业务所有权迁移（H01 第二阶段）

> 状态：目标设计。本文把 [Host 与协议设计](./host-protocol-design.md) §4 的六步切换从画布推广到其余五个业务域；已交付的第一阶段（画布）以该文 §4.1、[架构](../guides/architecture.md) §5 与[实施记录](../status/platform-implementation-status.md) H01 行为准，本文不复述，也不把任何目标行为写成已上线。
> 范围：settings、session、agent、filesystem、git 五个域的所有权切换、契约、数据、代码布局、实施批次与验收；画布域只在需要对齐时引用。
> 2026-09-19：桌面壳已换成 Electron，本文提到 Tauri 的部分是换壳之前写下的，只作为当时的方案记录；壳的现状见 [Electron 迁移](./electron-migration.md) 与 [架构](../guides/architecture.md)。

## 0. 结论

| 决定            | 内容                                                                                                                                                                                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目标            | 五个域逐域把**写入所有权**移到 Go Host。每个域切换后 Runtime 对应路由只回 `ownership_moved`（HTTP 409），读取继续作为只读后备；执行能力（PTY、文件、Git 命令、Hook）原地保留。六个域全部 `owner=host, phase=settled` 后 `apps/runtime` 改名 `apps/worker`。    |
| 顺序            | 基础批（多域所有权记录、事件流、HTTPS 切换、反向导入）→ settings → filesystem → session → agent → git。顺序按「Host 侧新增状态少、被后续域依赖多」排，不按用户可见价值排。                                                                                     |
| 机制            | 完全复用第一阶段：`write_ownership` 单行记录、单调 epoch、settled/switching/rolling_back 三相、导出 → staging 导入 → 投影 → 逐项核验 → 经 Worker 通道下发 epoch。差别只有两处：记录从「domain=canvas」放宽为六个域各一行、各自独立 epoch；切换入口增加 HTTPS。 |
| 通道            | HTTPS `/rpc/armadra.v1.*Service/*` 承载客户端命令与查询；Host↔Worker 帧协议（stdio 子进程或本机私有 socket）承载执行、所有权与 Worker 上报；新增一条 Host→客户端 WSS 事件流，六个域共用一条 durable sequence，替代画布 3 秒轮询。终端字节流不进业务事件流。   |
| 数据            | Host 迁移 v6–v10 各对应一个域；Runtime 迁移 0010 为其余五域补所有权行，0011 记录反向导入账本，0012（退役业务表）只在改名步骤执行。所有映射保留原 ID 与时间戳；核验差异即中止。                                                                                 |
| 永远留在 Worker | PTY/进程/tmux/Session Host 与回放日志、Hook 端点与节点令牌、待答权限文件、文件系统与回收站、Git 命令与锁、浏览器 profile、本机 CLI 配置与用量/转录文件、执行收据（prompt 投递、命令会话）。                                                                    |
| 不做            | 双写；自动切换；按版本重建数据库；把终端字节改走业务事件流；多人租约；在改名前做与切换无关的目录移动。                                                                                                                                                         |

## 1. 范围与分期

### 1.1 域的定义与当前落点

「Runtime 表」列的是 `apps/runtime/migrations/0001`–`0009` 中的表；「Runtime 路由」取自 `apps/runtime/src/lib.rs` 路由表；「Host 现状」指 `apps/host/internal/storage/schema.go` v1–v5 已有的表与 `server/scopes.go` 的授权面。

| 域         | Runtime 表                                                                                                                        | Runtime 路由前缀                                                                                                                                                               | Host 现状                                                                               | 切换后 Host 拥有                                                                                                                          | 切换后仍在 Worker                                                                                                                       |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| settings   | 无表；`<数据目录>/settings.json`（`settings.rs`）                                                                                 | `/api/settings`、`/api/ssh/hosts/*`、`/api/agents`（列表部分）                                                                                                                 | `settings:read/write` 授权面；无存储                                                    | 偏好文档（通用、白板、通知、快捷键三层、Agent 自定义定义、用量/资源阈值、SSH 执行主机注册）                                               | 执行主机本地项：`terminal.backend`、PATH 补齐、`browser.executable`、电源策略、tmux 配置——拆到独立的 `worker-settings.json`             |
| filesystem | 无表（`workspaces.root_path` / `execution_host_id` 已随画布域迁移）                                                               | `/api/workspaces/{id}/{files,file,file-*,imports,language-service}`、`/api/workspaces/{open-directory,remote,import}`                                                          | `files:*` 授权面、`command_roots`（v3，仅自动化）、H02 的 JSON 代理与远端 Worker 客户端 | 工作区根注册（冻结的规范路径 + executionHostId）、权限判定、监听订阅登记、写操作收据                                                      | 文件读写、回收站、监听、搜索索引、语言服务探测、上传/下载字节                                                                           |
| session    | `terminal_sessions`；`terminal_logs` 留在 Worker                                                                                  | `/api/terminals/*`、`/api/workspaces/{id}/sessions`                                                                                                                            | `command_sessions`（v3，仅自动化命令会话）                                              | 会话意图与元数据（id、session_key、节点绑定、kind、agent、cwd、冻结启动定义、状态投影、generation、attach 状态、终止意图）、创建/启动决定 | PTY、`backend_ref`、回放日志、generation 的产生、写入门与输入序号、上下文用量缓存、会话 GC                                              |
| agent      | `agent_status`、`agent_approvals`、`agent_mailbox`、`agent_deliveries`、`agent_handoffs`、`agent_handoff_outbox`、`context_links` | `/api/approvals/*`、`/api/control/confirm/*`、`/api/agent-status/*`、`/api/workspaces/{id}/{deliveries,handoffs,context-links,nodes/*/context-usage}`、`/api/agents/*/hooks/*` | 无                                                                                      | 状态投影、审批记录与答复、消息箱、投递记录、交接与投递 outbox、上下文链接投影（由画布边派生）                                             | Hook 端点/令牌/待答文件、归一化与 reduce、转录读取、投递写入门、`agent_prompt_deliveries`、`hook_installs`、`conversations`、上下文用量 |
| git        | 无表；内存操作队列（`git_repository.rs`）与 clone 任务                                                                            | `/api/workspaces/{id}/git/*`、`/api/git/clone*`                                                                                                                                | `git:*` 授权面；`GithubService`（v4）已在 Host                                          | 操作身份与队列（operationId、状态、前置版本、收据）、仓库状态快照缓存、clone 任务、worktree 绑定校验                                      | Git 命令执行、仓库级锁、进度、冲突文件、AI 提交信息生成（读本机凭据）                                                                   |

`browser_sessions`、`usage`、`resources`、`power` 不在本文五个域内：它们是执行主机事实，按 [Host 与协议设计](./host-protocol-design.md) §1 归 Worker，Host 只经授权代理与事件流转发。

### 1.2 切换顺序、依赖与回滚

| 序  | 域         | 放在这里的原因                                                                                                                        | 依赖                                                                   | 回滚代价                                                                           |
| --- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 0   | 基础批     | 多域所有权记录、事件流、HTTPS 切换、反向导入是每个域都要用的机制；先在画布域上验证，再给新域用                                        | 画布域已 settled（第一阶段）                                           | 无业务数据变化；只回退代码                                                         |
| 1   | settings   | Host 新增状态最少（一份文档 + 执行主机注册），没有进程或流；用它把「五步切换 + HTTPS 入口 + 反向导入」端到端走通                      | 基础批                                                                 | 低：反向导出就是一份 JSON 文档与执行主机列表                                       |
| 2   | filesystem | 没有 Host 业务表，本质是把 H02 的 JSON 代理换成类型化 `filesystem.proto`；建立 Host 直接驱动 Worker 根与文件通道，被 session/git 复用 | settings（执行主机注册决定路由到哪个 Worker）                          | 低：无数据迁移，回滚即路由切回                                                     |
| 3   | session    | 会话元数据是 agent 域全部记录的锚点（`session_id + generation`）；必须先于 agent                                                      | filesystem（根注册与 executionHostId 解析）、事件流（`terminal.exit`） | 中：会话行数少，但存活会话需要 Host→Worker 重认领；回滚要求无正在切换的 generation |
| 4   | agent      | 状态、审批、消息箱、交接都引用会话；Hook 上报改为 Worker→Host 上报                                                                    | session                                                                | 中高：消息箱与交接 outbox 有进行中的队列；回滚窗口要求队列排空                     |
| 5   | git        | 表面最大（`git_repository.rs` 3k 行 + 集成/引用/储藏子模块）、外部 Git 并发最难对账；最后做，且只迁移操作身份与快照，不迁移命令执行   | filesystem（根通道）、画布（Frame↔worktree 绑定）、事件流             | 低（无持久数据）但需要队列为空                                                     |

每个域独立 epoch，独立切换与回滚；不允许一次命令切多个域。域间依赖只表现为「前置域必须 `owner=host, settled`」，由 `OwnershipService.BeginSwitch` 检查并以 `FAILED_PRECONDITION` 语义（现有错误码用 `CONFLICT` + 原因键 `ownership.dependency.unsettled`）拒绝。回滚方向相反：回滚 session 前必须先回滚 agent。

### 1.3 每个域切换后的 Runtime（Worker）职责边界

| 域         | Host 决定                                                        | Worker 执行                                                           | Worker 上报（经 Worker 通道事件）                                            |
| ---------- | ---------------------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| settings   | 偏好文档的校验、revision、事件                                   | 读取 Host 推送的偏好投影（自定义 Agent、SSH 主机）；本地项自管        | 本地项摘要（后端种类、浏览器可用性）只进 Hello，不进业务事件                 |
| filesystem | 授权、根注册、路径归属、操作收据                                 | 所有 I/O、监听、搜索、回收站                                          | `file.changed`（含 dev/inode 或轮询来源标记）、监听失效                      |
| session    | 是否创建/启动、启动定义冻结、节点绑定、状态投影、终止意图        | 起 PTY、分配 generation、附着与写入门、回放、休眠与 GC                | `SessionRunStarted/Exited/Lost`、generation 变化、附着计数                   |
| agent      | 状态 reduce 结果的持久化、审批记录、消息箱、投递记录、交接状态机 | Hook 端点与令牌、归一化、转录读取、终端投递、待答文件写入、交接包投递 | 归一化后的 Hook 事件、投递收据（Submitted/NotWritten/Unknown）、审批请求出现 |
| git        | 操作身份、排队与串行规则、前置版本比对、状态快照缓存、clone 任务 | 运行 Git 命令、持仓库锁、解析输出、冲突检测                           | `OperationChanged`、`RepositoryChanged`、`ConflictDetected`、进度            |

Worker 在任何域都不再做业务授权：请求到达 Worker 时已由 Host 校验设备、作用域与 revision；Worker 只重检执行主机事实（generation、文件版本、仓库 HEAD、路径在根内）。

### 1.4 永远留在 Worker 的数据

| 类别          | 数据                                                                                                              | 理由                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 进程          | PTY、tmux server、Session Host 句柄、命令会话进程、浏览器进程                                                     | 无法跨进程持有                                       |
| 执行事实      | `terminal_logs`、`backend_ref`、generation 计数、输入序号、`agent_prompt_deliveries`、`command_sessions` 执行收据 | 与写入动作同事务，是「是否已经写进 PTY」的唯一证据   |
| 本机文件      | 工作区文件、`.armadra/`、回收站、Hook 端点文件、节点令牌、待答文件、浏览器 profile                                | 只在执行主机上有意义；远端 Worker 不能用本机绝对路径 |
| 本机 CLI 状态 | `hook_installs`、`conversations` 索引、用量与成本扫描缓存、CLI 版本探测缓存                                       | 读的是执行主机上各 CLI 自己的配置与转录              |
| 本地设置      | `worker-settings.json`（终端后端、PATH、浏览器可执行文件、电源策略）                                              | 执行主机差异化配置，不随设备同步                     |

## 2. 契约

### 2.1 通用规则

沿用 [Host 与协议设计](./host-protocol-design.md) §3.3 的兼容规则，本阶段新增的 `.proto` 统一：

| 规则       | 约定                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 字段号分组 | 1–9 身份与作用域；10–29 业务字段；30–38 状态枚举；39 `reason_code`；40–49 时间戳（`*_unix_ms`）；50 `revision`；51 `deleted`；oneof 从 100 起，各域预留 20 个号    |
| 请求信封   | `meta = 1`（`CommandMeta`）、`operation_id = 2`（变更必填）、`expected_revision = 3`、业务字段从 10 起                                                             |
| 响应信封   | 变更响应恒为 `{ entity = 1, receipt = 2 }`，`receipt` 复用 `CanvasOperationReceipt` 的形状，抽成 `common.proto` 的 `OperationReceipt`（canvas 保留旧消息名作别名） |
| 枚举       | 0 恒为 `*_UNSPECIFIED`；未知值在三端都是错误，不映射成默认                                                                                                         |
| 幂等       | `operation_id` 按 principal/workspace/域 命名空间存储并校验请求摘要；同 id 同内容返回原收据（`replayed=true`），同 id 不同内容 `CONFLICT`                          |
| CAS        | 每个实体带 `revision`；变更携带读到的 revision，0 表示「从未创建」；删除留带 revision 的墓碑                                                                       |
| 事件       | 实体变化与存储同事务写入 `events`，六个域共用一条按 Host 的 durable sequence；保留 7 天或 `event_floor`                                                            |
| 大载荷     | 白板快照、交接包、审批请求原文、Git 动作参数走 `bytes + sha256 + schema_version` 的不透明载荷；不展开成字段                                                        |
| 版本       | 协议 major 1 不变；每新增一个 `.proto` 提升 minor，并在 Hello 的 `capabilities` 报告 `<domain>.host.v1`；未切换的域在 `capability_status` 报 `ownership.runtime`   |

方法命名沿用已有约定：无 `service` 定义，HTTPS 路径为 `/rpc/armadra.v1.<Domain>Service/<Method>`，请求/响应消息为 `<Method><Domain>Request/Response`。每个 `.proto` 至少一个 `proto/fixtures/*.hex` 与三端契约测试。

### 2.3 `events.proto` 与 Host→客户端事件流

| 消息               | 字段（号）                                                                                                                                                                                                                                                                                                      | 说明                                                                                                         |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `EventDomain`      | 同 `WriteOwnershipDomain` 取值                                                                                                                                                                                                                                                                                  | 一个事件只属于一个域                                                                                         |
| `EventEnvelope`    | `sequence`(1) `transaction_id`(2) `operation_id`(3) `transaction_index`(4) `transaction_size`(5) `workspace_id`(6) `domain`(7) `kind`(8, string) `entity_id`(9) `revision`(50) `deleted`(51)；oneof `entity`：canvas 100–119、settings 120–139、filesystem 140–159、session 160–179、agent 180–219、git 220–239 | 与 `CanvasEventEnvelope` 同源；画布 oneof 成员按原字段名映射，`CanvasService/SubscribeEvents` 继续返回旧信封 |
| `EventStreamFrame` | oneof：`subscribe`(100) `page`(101) `heartbeat`(102) `ack`(103) `error`(104)                                                                                                                                                                                                                                    | WSS 二进制帧，帧上限 1 MiB                                                                                   |
| `SubscribeEvents`  | `after_sequence`(1) `workspace_ids`(10) `domains`(11) `page_bytes`(12)                                                                                                                                                                                                                                          | 一条连接一个订阅；游标只前进                                                                                 |
| `EventPage`        | `status`(30：OK / SNAPSHOT_REQUIRED / CURSOR_AHEAD) `events`(10) `next_cursor`(11) `min_cursor`(12) `high_watermark`(13) `has_more`(14)                                                                                                                                                                         | 与 `CanvasEventPage` 同形                                                                                    |
| `StreamAck`        | 复用 `common.proto`                                                                                                                                                                                                                                                                                             | 客户端每页回 `received_through`，服务端据此释放队列预算                                                      |

流的行为：

| 项                  | 约定                                                                                                                                                                                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 入口                | `GET /ws/armadra.v1.EventStream`，升级时按 `server/proxy.go` 的现有规则校验精确 Origin 与 `SameSite=Strict` 会话 Cookie；无 CSRF 头（浏览器握手不能带）；工作空间按会话授权收窄，未授权的 `workspace_ids` 直接 `PERMISSION_DENIED` 关闭                                                                |
| 追赶                | 订阅先由 HTTPS 快照/事件页追到 `high_watermark`，再由流推送；服务端在 `subscribe` 后先发一页历史（≤ `page_bytes`），`has_more=true` 时客户端继续用 HTTPS 追，追平后才切到推送——避免流承担无界回放                                                                                                      |
| 排序                | 六个域共用 `events.sequence`；同一 `transaction_id` 的事件连续且带 `transaction_index/size`，客户端整组应用                                                                                                                                                                                            |
| 流控                | 单订阅者队列 4 MiB；超限发 `error{RESOURCE_EXHAUSTED}` 后关闭，客户端带游标重连；审批与控制确认类事件（agent 域 `approval`、session 域 `run`）走独立高优先级队列                                                                                                                                       |
| 心跳                | 25 秒服务端心跳；客户端 60 秒无帧则重连；重连退避复用 `apps/web/src/api/events.ts` 的 1s→10s                                                                                                                                                                                                           |
| 与 Runtime 流的关系 | 未切换的域继续由 Runtime `/api/workspaces/{id}/events` 推 JSON 事件；前端适配层把 `EventEnvelope` 投影成现有 `WorkspaceEvent` 类型（`agent.status`、`terminal.exit`、`file.changed`、`board.changed`…），`onWorkspaceEvent` 订阅接口不变，只是来源按域的所有权切换。同一事件类型在任一时刻只有一个来源 |
| 终端字节            | 不在此流；仍走 Worker 的 `/api/terminals/{id}/ws`（桌面直连或 Host 代理），按 `session/generation` 排序                                                                                                                                                                                                |

### 2.9 `worker.proto` 扩展：常驻通道与上行

第一阶段的 Worker 通道是 Host 发起的请求/响应。本阶段需要 Worker 主动上报（Hook 事件、会话退出、文件变化、Git 进度），因此扩展为双向但仍单连接：

| 项         | 约定                                                                                                                                                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 承载       | 同一套 4 字节长度前缀帧：① stdio 子进程（命令 Worker、远端 SSH Worker、切换 Worker，现状）；② 本机私有 socket（常驻 Runtime 在 `endpoints.json` 发布的 `socket`/命名管道上新增 `worker` 服务，Host 经 `runtimelink` 拨号）。远端 Worker 的上行经同一条 SSH 内流回传 |

### 2.11 HTTPS 上的切换、回滚与维护窗口

第一阶段的维护窗口靠数据目录锁实现（Host 必须停止）。HTTPS 入口的 Host 在运行，窗口改为**双方同时进入 `switching` 相**，同样没有任何一侧能写：

| 步骤 | 动作                                                                                                                                                                                                                                              | 失败处理                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 0    | 客户端经本机 OS 控制通道申请 `maintenance_token`（与配对票据同机制，2 分钟、一次性、绑定 Host 指纹与域）；HTTPS `BeginSwitch` 必须带该 token、`settings:write`、owner 角色与 CSRF                                                                 | 无 token 的远程设备永远不能发起切换                                                                          |
| 1    | Host 校验依赖域（§1.2）、`expected_epoch`；写 `phase=switching`（`reason=ownership.switch.pending`），并广播 `ownership` 事件；自身从此拒绝该域写入                                                                                               | 任一校验失败：不改记录，返回 `CONFLICT` + 原因键                                                             |
| 2    | 经 Worker 通道 `SetWriteOwnership{phase=switching}`：Runtime 把该域置为 switching，拒绝写入，排空进行中的写事务（session/agent：等待当前 hook 事件与投递门返回；git：拒绝新入队、等待 RUNNING 结束或标记 UNKNOWN_OUTCOME），然后回应              | 30 秒未回应：进入 `ownership.switch.unknown`，窗口保持打开，操作者重跑同一命令收敛                           |
| 3    | `ExportDomain`：Runtime 用 `sqlite_snapshot.rs` 的一致性快照导出该域的表（复用 `migration_export.rs` 的清单格式，`tables` 限定该域），返回导出包路径与 manifest 摘要                                                                              | 导出失败：`SetWriteOwnership{phase=settled, owner=runtime}` 回到切换前记录，`reason=ownership.switch.failed` |
| 4    | Host `import`（现有 `migration.Stage`，`purpose=<domain>`）→ `Materialize` → `Verify`（§3.3 核验项）                                                                                                                                              | 任一差异：报告返回给调用方，记录恢复到切换前 settled，Runtime 同步恢复                                       |
| 5    | 核验通过：Host 写 `owner=host, epoch+1, settled`，下发 `SetWriteOwnership{owner=host, epoch}`；Runtime 对应路由从此回 `ownership_moved`；Host 开始接收该域写入并对存活对象重认领（session：`ReclaimRuns`；git：队列为空即可；agent：outbox 认领） | 应答丢失：`GetWriteOwnership` 读 Runtime 实际值收敛（与第一阶段相同）                                        |

回滚（`Rollback`）步骤相同、方向相反，且第 3 步换成 Host 反向导出、第 4 步换成 Runtime `ApplyReverseExport`（§2.12）。`ownership status` 与 `OwnershipService/List` 都能看到 `switching` 与 `unknown`，前端把该域置为只读并显示原因键。CLI 入口保留，用于 Host 无法启动时的离线操作；两者共用同一状态机（`internal/ownership`）。

### 2.12 反向导出重新导入 `canvas.db`

第一阶段只写出反向导出包（`canvashost/export.go`，`formatVersion=1`：每工作空间一个实体文件 + `index.json` 摘要），没有导入方。本阶段补齐：

| 项             | 约定                                                                                                                                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 包格式         | 提升为 `formatVersion=2`：`index.json` 增加 `domain`、`epoch`、`eventSequence`、`hostId`、每文件 `entityCount`；实体文件是该域 Protobuf 消息的长度前缀序列；版本 1 仍可被读取（只有 canvas 域）                                                      |
| 入口           | 离线：`armadra-runtime import-host-export --domain D --package DIR --expected-epoch N`（持数据目录锁，Runtime 未运行）；在线：Worker 通道 `ApplyReverseExport{domain, package_path, index_sha256, expected_epoch}`（Runtime 处于 `rolling_back` 相） |
| 幂等           | Runtime 迁移 0011 新增 `host_imports(import_id, domain, epoch, index_sha256, applied_at)`；同 `import_id` 重放直接返回原结果；不同摘要拒绝                                                                                                           |
| 映射           | Host 实体 → Runtime 行，与 `materialize.go` 的投影严格互逆（§3.3）；保留 ID、`created_at/updated_at`；Host 侧 `revision` 不写入 Runtime（Runtime 用时间戳 CAS），但记入 `host_imports` 供再次切换时比对                                              |
| 事务           | 整包一个 `BEGIN IMMEDIATE`：先删该域该工作空间的现有行（Host 持有期间 Runtime 没写过，这些行等于切换前导出的内容），再插入；任何一行失败整包回滚                                                                                                     |
| 核验           | 导入后 Runtime 立即再导出一份，Host 用同一套 `Verify` 与自己写出的包比对；通过才允许第 5 步把 epoch 交回                                                                                                                                             |
| 不能回滚的情况 | Host 持有期间产生的事件里包含 Runtime 不认识的实体类型（例如更高 `schema_version` 的白板快照、新枚举值）：`Verify` 报 `reverse.unsupported_entity`，只能 `--accept-export-only`                                                                      |

`--accept-export-only` 语义不变：操作者明确接受 Host 期间的改动只存在于导出包里。

### 6.3 「未切换前后行为一致」对照测试

原则：同一套黑盒断言在 `owner=runtime` 与 `owner=host` 两种状态下各跑一遍，结果经规范化（去掉 id、时间戳、revision/updatedAt、序号）后逐字节相等。差异必须是本文明确声明的（例如 `revision` 取代 `updatedAt` CAS、事件来源不同），并登记在脚本的 `expectedDifferences` 表里；未登记的差异即失败。

| 层次       | 手段                                                                                                                                                       | 覆盖                                                |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
