## 1. 产品目标与已确认边界

Armadra 是以画布为主工作面的开发平台。终端、Agent、文件、浏览器与自动化节点共享空间；常驻服务管理执行、数据和设备连接。用户关闭页面后，已启用的计划继续由后台执行。

已确认的术语：

- Loop / Cron / Schedule：Agent 内部循环的可视化与平台独立调度两套能力，均需实现。
- SSH：连接远程执行主机；同时建设允许其他设备连接本机的 Host 服务。
- AI commit message：由模型生成 Git 提交信息；另外实现 Agent/终端自动命名。
- 桌面 Command W/窗口叉号只关闭前台并保留后台；Command Q/托盘退出明确停止本机受管后台。浏览器标签关闭仍只断开客户端。
- 能力继承：自定义 Agent 继承基础适配器，再经过 CLI 版本与执行主机能力判断。
- 移除任务看板、会话任务卡片、任务列拖动和任务排序；保留节点备注。接续实现遵循最新界面决定：不恢复已移除的装饰性标签、自定义节点颜色和颜色标记入口。
- 保留自由绘画、文本、图片及 Frame；绘画和会话均不转换成任务卡片。
- GitHub Issues 的列映射归属 GitHub 面板，不恢复应用级 Kanban。Issue 重新打开、关闭和状态移动均需支持；PR 使用独立列表与详情。

“资源面板”指主机/会话监控界面，与移除的任务看板无关。自动化卡片是画布执行节点，与被移除的会话任务卡片无关。

## 4. 信息架构与组件位置

主工作区始终显示画布。左侧管理 Host、工作空间、画布与会话导航；底部 Dock 放创建和绘图；右侧使用同一个工作面板容器，在文件、Git、GitHub、自动化和资源页间切换。用户可以固定面板，但不增加常驻的第二套任务工作面。

| 位置         | 组件                                     | 内容                                                   |
| ------------ | ---------------------------------------- | ------------------------------------------------------ |
| 左侧顶部     | HostSwitcher                             | 本机/远程 Host、连接状态和执行位置                     |
| 左侧树       | WorkspaceTree / CanvasTree / SessionList | 项目、画布、正在运行的会话；仅导航，不含任务列         |
| 节点头部     | AccountBindingBadge                      | 账号字段预留，未启用时不占位置                         |
| 终端更多菜单 | AgentActionsMenu                         | 命名、交接、循环观察、保存输出、进程操作               |
| 画布         | AgentActivityNode / AutomationNode       | 原生循环观察卡片、平台定时节点，两者视觉与数据类型分开 |
| Frame 头部   | WorktreeBindingBadge                     | 分支、路径、脏文件数、初始化脚本状态                   |
| 右侧 Git     | SourceControlPanel                       | Changes / Branches / History / Worktrees 四个页签      |
| 右侧 GitHub  | GitHubPanel                              | Issues / Pull requests；上方仓库与筛选，下方详情       |
| 右侧资源     | ResourcePanel                            | Host 总览、会话表格、孤立会话；可跳回画布节点          |
| 设置         | Host / Agents / Keyboard / Updates       | 后台服务、继承能力、快捷键、更新配置                   |

Issue 状态映射使用 Issues 页中的“按状态分组”列表和 `Move to…` 操作；可切紧凑状态分栏，但只显示真实 GitHub 条目，首版不提供拖动排序。原始 Issue 内容与会话通过 `ExternalReference` 关联，不把所有会话复制成 Issue 卡片。

窄屏使用底部导航和全屏详情 Sheet；画布仍可平移缩放，选中终端/编辑器/浏览器后进入单节点焦点视图。设备宽度改变不影响宿主进程、文件状态或计划。

### 4.1 连接入口与文件拖拽

节点连接按钮保持几何中心贴合左右边界。鼠标圆点 14px、命中区 34px；触屏圆点 16px、命中区 36px，低缩放时保持可辨认。命中区域主要向外扩展，不覆盖节点正文。扩大范围后显式记住本次手势的起点节点，保留原生终点命中、自连/重复连校验及单步撤销；取消、切画布和卸载必须释放手势状态。

文件树与 Files 节点可将文件拖入终端插入路径，或拖到画布打开预览，具体身份、路径和平台规则见[编辑器设计](./editor-browser-design.md)。这两种动作都不创建任务卡片。

## 5. 领域语言

| 实体              | 定义与边界                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------- |
| Host              | 对设备提供服务的常驻进程（写这份文档时是 Go 进程，现已并入 TS core），一个数据目录一个主实例      |
| Worker            | 运行于某执行主机、操作该主机文件/Git/CLI 的执行进程（写这份文档时是 Rust 进程，现已并入 TS core） |
| Workspace         | 某 Host 下绑定执行主机和根目录的项目                                                              |
| Canvas            | 工作空间内的画布；旧 `Board` 的新业务名称                                                         |
| Node              | 画布展示实体，持有 sessionId/scheduleId 等引用                                                    |
| Session           | 执行实体，离开画布或关闭页面后仍可存在                                                            |
| SessionRun        | 某一 generation 的实际 CLI/PTY 进程运行                                                           |
| Automation        | 平台拥有的计划定义；与可视化节点寿命分开                                                          |
| AgentActivity     | CLI 自己产生的循环/子任务活动，可观察能力由适配器声明                                             |
| WorktreeBinding   | Frame 与 Git worktree 的关联；不是新的任务分组体系                                                |
| ExternalReference | GitHub Issue/PR 与会话、分支、worktree 的轻量关联                                                 |

所有执行地址含 `hostId / executionHostId / workspaceId`。所有会话行为使用 `sessionId + generation`，避免节点移动、重开或复用时控制了旧进程。

## 6. 迁移与移除看板

1. 枚举当前 `kanban` schema、数据库列、保存队列、模型默认值和测试；入口盘点不以文件名猜测。
2. 新协议与 UI 统一使用 Canvas，过渡适配层维护旧 Board ID 的一一映射，画布本身不删除。
3. 对数据库做一致性备份，导出旧 `columns/cards` 至迁移归档，记录版本和校验和。
4. 移除任务看板 UI、任务列/任务排序动作及会话任务卡片语义。保留 `note`、位置、Frame、白板资产及上下文链接；历史标签只进入兼容归档，不恢复装饰性标签或自定义节点配色界面。自由绘图的绘画样式不受影响。
5. 新写入不再产生 Kanban 数据；过渡期旧列只读且不再由旧客户端写回。旧客户端连接新 Host 时必须经过兼容协商。
6. 待导入验证通过及回滚窗口结束，再用正式数据库迁移移除旧列。禁止通过“版本不匹配就重建数据库”的方式上线。

迁移测试必须覆盖有/无 Kanban、备注含中文、图片、嵌套 Frame、未结束会话、正在等待的依赖节点和进行中的消息。运行会话重认领失败时呈现为待恢复，不假装仍运行。

## 7. 当前工程的接入方式

写这份文档时保留的是 `apps/web`、`apps/desktop`、`apps/runtime`、`crates/hook` 的已有业务基础，新增 Go Host 与协议目录后逐步切换；现在 Runtime 与 Host 已合并成 `apps/desktop/src/core/`，由 Electron 桌面壳与无窗口服务器壳（`apps/server`）装配，下表按当时的入口记录目标变化，仅作历史参考，不代表现状目录结构。

| `apps/web/src/terminal/TerminalSurface.tsx`   | 挂载只请求附着，不能决定是否创建/启动后台任务             |

## 8. 共同行为与质量约束

- 每个异步动作返回可查询的 operationId；“已接受”“已执行”“执行失败”“结果未知”分开。
- 任何后台功能都有状态读取与恢复路径；仅有前端按钮不算交付。
- 所有外部副作用在后端执行时检查身份、作用域及前置版本；按钮隐藏不作为权限控制。
- 离线可查看缓存；终端输入、提交、PR 合并、审批不做静默离线排队。
- 中英文本地化同步，状态不能只用颜色表达，菜单及表单可用键盘完成。
- 数据库状态改变与事件发布采用事务 outbox；进程输入及外部 API 的结果不虚称端到端 exactly-once。
- `unknown / unsupported / stale / denied / disconnected` 都是有效 UI 状态，不能统一显示为 0 或成功。
- 成本、内存与帧率阈值均为待测的产品预算；发布前留下平台、硬件、工作负载和结果记录。

## 10. 最终场景验收

1. 本机打开仓库，在 Frame 中创建 worktree，启动两个不同 Agent；节点各自显示自己的状态与内存。
2. Agent A 结束后触发 B；平台计划在所有页面关闭后仍执行，重新打开可查看运行历史。
3. 将 B 的会话交给另一 Agent，目标收到预算内的上下文与正确 worktree，不自动替换来源会话。
4. 编辑器修改文件，处理外部修改冲突，选择 hunk 暂存，AI 草拟提交信息，提交并推送。
5. 查看提交图，创建 PR，查看检查和评审，定位到关联终端；Issue 状态变化回写 GitHub。
6. Agent 使用受控浏览器验证本地页面；手机查看同一画面、终端和文件，断线后正确恢复。
7. Windows 上关闭桌面 UI、重启 core（写这份文档时方案是分别重启 Go Host 与 Rust Worker，现已合一），活跃 ConPTY 会话分别经验证仍可附着。
8. 资源面板定位高占用会话；节点隐藏只降低渲染消耗；工作完成后防休眠租约释放。
